## Phần đã triển khai

- Aggregate `Disaster` thuần Java, validation đúng P00 và lifecycle một chiều
  `ACTIVE → RESOLVED`. Disaster `RESOLVED` immutable, không reopen; optimistic
  version tăng sau mỗi patch và stale write trả `409 STALE_VERSION`.
- Application use cases/ports tách khỏi Spring/JPA/HTTP. JPA adapter dùng conditional
  update theo `id + version`; list lọc `status/type`, phân trang ở DB và sort ổn định
  `createdAt` rồi `id`.
- Flyway `V3__disasters.sql` tạo bảng/ràng buộc/index của module, không seed và không
  FK/cross-module join. Hibernate chỉ validate schema.
- E03/E04 cho CITIZEN và AUTHORITY; E05/E06 chỉ AUTHORITY. DTO HTTP riêng, strict
  body/query/media/UUID validation, no-store và error envelope theo P00. Runtime
  OpenAPI công bố E01–E06 qua hai implemented slices.
- S05 `/operations/disasters` cho AUTHORITY: filter, pagination, list/detail panel,
  create/edit, xác nhận resolve, loading/error/empty và xử lý 401/403/409. Route được
  auto-register bởi convention `frontend/src/features/**/routes.tsx`; không cần sửa
  router, auth client hay global CSS.

## Published contract cho B2

Các type public nằm đúng tại `com.gdrn.disaster.application.contract` và không phụ
thuộc framework:

```java
public interface DisasterQuery {
    Optional<DisasterSnapshot> findById(UUID disasterId);
    Map<UUID, DisasterSnapshot> findByIds(Set<UUID> disasterIds);
}

public record DisasterSnapshot(UUID id, DisasterState status) {}
public enum DisasterState { ACTIVE, RESOLVED }
```

Spring cung cấp bean `DisasterQuery`; B2 dùng port do Reporting application sở hữu,
adapter gọi interface published này, không import Disaster infrastructure/repository/entity. Missing ID trả
`Optional.empty()` hoặc bị bỏ khỏi batch map. Batch nhận tối đa 100 distinct IDs,
empty input trả immutable empty map; null input/member hoặc quá giới hạn ném
`IllegalArgumentException`. Kết quả map/snapshot immutable và phản ánh trạng thái đã
commit ở thời điểm query. B2 dùng `ACTIVE` để cho phép verify, missing → 404 và
`RESOLVED` → 409 theo P00; C1 không quyết định error HTTP thay B2.

## Dùng màn hình tạo disaster

1. Chạy `scripts/local.ps1 -Action start`, mở `http://127.0.0.1:5173/login` và đăng
   nhập bằng tài khoản `DEMO_AUTHORITY_*` trong `.env`.
2. Chọn **Thảm họa** trên thanh điều hướng hoặc mở `/operations/disasters`.
3. Chọn **Tạo thảm họa**, điền tên, loại, mức độ, mô tả, vĩ độ và kinh độ rồi lưu.
   Disaster mới luôn là `ACTIVE`, version `0`; ID/timestamp do backend tạo.
4. Chọn một dòng để xem chi tiết. **Chỉnh sửa** gửi current version và chỉ field đổi.
   **Kết thúc thảm họa** có bước xác nhận; thao tác này không thể hoàn tác.

Conflict `409` được giữ thành thông báo và UI tải lại list/detail mới nhất, không tự
retry write. `401` xóa memory session theo shared client; `403` giữ phiên và báo lỗi.
